# مشاوير

واجهة توصيل عربية تعمل كـ PWA، ومجهزة للتحويل إلى Android APK عبر Capacitor.

## اتجاه المنتج

مشاوير هو أولًا تطبيق رحلات أفراد بين المستخدم والمندوب: طلب مشوار، تحديد الوجهة، حساب السعر، قبول المندوب، ومتابعة الرحلة حتى الوصول. توصيل المطاعم والبقالة والصيدلية والطرود خدمة إضافية داخل التطبيق وليست المسار الرئيسي.

## ما تم تجهيزه

- واجهة RTL عربية باسم «مشاوير» وبألوان حيوية وحركة توحي بالسرعة.
- واجهة مستخدم للبحث في المطاعم والبقالة والصيدلية وإضافة الطلب للسلة.
- عنوان نصي مع طلب صلاحية الموقع الجغرافي عند الحاجة.
- خيارات التسوية: دفعت للمحل، Vodafone Cash، InstaPay، أو الدفع عند الاستلام؛ وFawry ظاهر كخيار «قيد التحديث» فقط.
- واجهة مندوب بحالة متاح/غير متاح، الطلبات الخاصة به، والحالة والأرباح.
- لوحة إدارة للمحلات والطلبات والمندوبين والرسوم.
- ثلاث نقاط دخول منفصلة: مستخدم، مندوب، وإدارة، مع تحقق فعلي من دور الحساب.
- تسجيل المندوب من الواجهة يبدأ بحالة انتظار موافقة الإدارة؛ إنشاء حساب المدير محصور بالإدارة.
- تسجيل برقم الهاتف وكلمة مرور، وPIN استرجاع من 6 أرقام بدون رسائل مدفوعة.
- تحديد محاولات PIN وقفل مؤقت بعد المحاولات الخاطئة.
- جداول Supabase وRLS وبيانات تجريبية جاهزة.

## النواة التشغيلية للطلبات

- الطلب الواحد هو المصدر المركزي للحقيقة بين العميل والمندوب والإدارة.
- الحالات الموحدة: `pending` ثم `confirmed` ثم `searching_driver` ثم `assigned` ثم `driver_accepted` ثم `heading_to_pickup` ثم `arrived_pickup` ثم `picked_up` ثم `delivering` ثم `arrived_destination` ثم `delivered`.
- الحالات الاستثنائية: `cancelled` و`rejected` و`failed`.
- التعيين يتم عبر `assign_order` بصلاحية الإدارة فقط.
- تحديث الحالة يتم عبر `advance_order` مع التحقق من الدور والانتقال المسموح.
- كل انتقال يُحفظ في `order_status_history` وتُنشأ له إشعارات مرتبطة بالطلب.
- المندوب غير المعتمد يرى شاشة انتظار ولا يستقبل الطلبات.

## تشغيل التطبيق

```bash
npm install
npm start
```

افتح `http://localhost:4173`.

## إعداد Supabase

1. افتح SQL Editor في مشروع `mashwer`.
2. نفّذ `supabase/schema.sql`.
3. نفّذ `supabase/passenger_rides.sql`.
4. نفّذ `supabase/passenger_rides_production.sql`.
5. نفّذ `supabase/seed.sql` لإضافة التعريفة الافتراضية.
6. لا تحتاج إلى تفعيل Phone Provider أو SMS؛ الدخول بدون كود يستخدم هوية داخلية غير ظاهرة للمستخدم.
7. تأكد من إيقاف `Confirm email` في Authentication حتى يبدأ الحساب مباشرة بدون كود.
8. دوال PIN والاسترجاع موجودة داخل `schema.sql` وتعمل من قاعدة البيانات مع قفل مؤقت بعد المحاولات الخاطئة.
9. بعد إنشاء حساب المدير، غيّر دوره من SQL Editor إلى `admin` باستخدام رقم الهاتف بصيغة `+20...`.

المفتاح الموجود في `config.js` مفتاح نشر عام فقط، وليس مفتاح الخدمة.

## APK Android

بعد تثبيت Node.js وAndroid Studio:

```bash
npm run mobile:add
npm run mobile:sync
npm run mobile:open
```

تُبنى نسخة الاختبار من Android Studio، ثم يمكن تجهيز نسخة Google Play بعد اعتماد تدفق الطلبات والدفع.

## ملاحظات التشغيل في مصر

- الأرقام تُحوّل تلقائيًا إلى صيغة مصرية تبدأ بـ `+20`.
- الأسعار بالجنيه المصري.
- تحويل Vodafone Cash وInstaPay يحتاج رقم عملية أو إثباتًا، وتأكيد الإدارة قبل اعتبار الدفع مؤكدًا.
- القرية ومناطق التوصيل ورسومها يجب أن تُدار من لوحة الإدارة عند ربط شاشة الإعدادات النهائية.

## توصيل الأفراد

ملف `supabase/passenger_rides.sql` يضيف نواة رحلات الأفراد بدون التأثير على طلبات المطاعم الموجودة في `public.orders`.

- الرحلة تحفظ نقطة الانطلاق والوجهة والمسافة والمدة والسعر وقت الطلب.
- الإدارة تضبط سعر البداية وسعر الكيلومتر وسعر الدقيقة والحد الأدنى ورسوم الخدمة والإلغاء.
- عروض الرحلة تحفظ قبول أو رفض أو انتهاء كل مندوب بشكل مستقل.
- الدفع المبدئي في الـMVP: `cash` أو تحويل يدوي `vodafone_cash` و`instapay` مع رقم العملية ومراجعة الإدارة.
- Vodafone Cash وInstaPay ظاهرين في واجهة الدفع، ويطلبان رقم عملية للتحقق اليدوي.
- Fawry مضاف كخيار محجوز لكنه معطّل وموسوم «قيد التحديث» إلى أن يتم ربط حساب التاجر والـAPI.
- لا يوجد SMS OTP أو عمود OTP في نظام الرحلات.
- لا يجب اعتماد المسافة أو السعر القادم من المتصفح وحده؛ يجب أن يحسبهما خادم الخرائط أو Edge Function قبل إنشاء الرحلة.

واجهة طلب المشوار موجودة في `app.js`: تبحث عن العناوين وتحسب المسار ثم ترسل الرحلة عبر `create_passenger_ride`. ملف `worker.js` يمرر طلبات الخرائط عبر `/api/maps/*` عند نشر المشروع على Cloudflare. شغّل ملفات الرحلات بالترتيب أعلاه قبل اختبار الحسابات الحقيقية.

## نشر Cloudflare

```bash
npx wrangler login
npx wrangler deploy
```

يستخدم Worker افتراضيًا Nominatim للبحث عن العنوان وOSRM لحساب الطريق، ويمكن تغييرهما عبر `GEOCODING_URL` و`ROUTING_URL` في إعدادات Cloudflare.
